# ADR-0003: Managed native video process ownership

- Status: Accepted for development composition; permanent dependency and signed-artifact admission remain open.
- Date: 2026-09-27.
- Scope: Approved Sunshine/Moonlight migration; preserves ADR-0001 roles and independent Observe, Act and Control grants.

## Evidence

The [development attribution checkpoint](../evidence/2026-09-27-native-menu-app-tcc-attribution.md) compares the same verified portable host through a command-line parent, a signed app with a different designated requirement, and a signed app matching the installed development requirement. macOS attributed the command-line hierarchy to Codex. Launching an app through LaunchServices attributed Sunshine to the MacCompanion menu. The differing Developer ID requirement failed existing Screen Recording matching; the installed Apple Development requirement produced allowed ScreenCapture records and passed native launch, renewal and Stop.

This establishes a development ownership arrangement, not final signed-product acceptance. A process name or matching signing identifier alone is insufficient evidence of privacy attribution or consent continuity.

## Decision

The visible MacCompanion menu app owns the native host lifetime. It runs as an app through normal macOS launch/login mechanisms, and starts a subordinate finite supervisor and managed Sunshine child under the already-approved Control/capture owner. Sunshine gains no independent service, login registration, pairing store, grant authority or input permission. The Agent keeps the existing policy/network role and does not launch capture.

Screen Recording belongs to the responsible menu app with its exact applicable signing requirement. Development construction must retain the intended requirement and verify observed app attribution. Release signing is independently revalidated against its own requirement and consent; a development grant cannot certify another signing requirement. Do not reset privacy databases or add a broad permission workaround.

The supervisor and host are privately packaged code resources. Production construction must verify their closed artifact/dependency graph and signatures before execution. The upstream helper identifier is not used as a remote authority or independent TCC owner. New permanent target/signing inventory entries, if needed, follow execution-status gates before admission. No new SMAppService role is introduced.

Only the authenticated normal menu backend owner can start the host after current Control and actual capture geometry are established. Retain the original deadline and operation/surface binding; an endpoint, library, restart or lease renewal cannot extend authority. The parent-loss/finite supervisor remains a second termination boundary. Stop, grant loss, changed capture geometry, expiry or child failure joins drain before replacement and removes private credentials.

The native host has the existing sealed Desktop-only profile: no administration/plaintext listeners, upstream pair/resume/appasset routes, native input, audio stream or UPnP. The initial native route remains loopback. LAN requires its normative binding/admission work first. The authenticated MacCompanion primary carries enrollment and input; client presentation and the final menu input permit remain mandatory.

## Production integration work still required

1. Promote reviewed first-party wrappers into the production source graph and admit the exact pinned foreign dependencies, notices, privacy and artifact inventory. No release target links `Experiments/`.
2. Construct the containing-app package with verified native code resources, preserving the intended development and release requirements independently.
3. Inject the Mac and iOS factories into their normal application owners and repeat the signed normal UI journey through app-owned capture rather than a command-line parent.
4. Verify actual menu input, installed-app lifecycle and permission recovery; then LAN and physical iPhone acceptance. Source delivery/rebuild and release evidence remain independent open lanes.

The current attribution test has synthetic custody/local consent and generated bootstrap, and does not post real input. It does not certify the final production binary graph, audio/privacy declaration, App/Window capture or visible-area bitrate.
