# Stage 0 Permission and Process Matrix

Status: baseline to verify on clean physical machines. A row is not passed until its grant, denial, revocation, relaunch, lock, and uninstall behavior is recorded for every supported OS.

| Capability | Executor | Required authority | Allowed host state | Onboarding owner | Revocation behavior | Stage 0 evidence |
| --- | --- | --- | --- | --- | --- | --- |
| Private listener | Agent | Selected-interface network access; containing-app Local Network usage description and responsible-code attribution on macOS; server entitlement only if the final sandbox requires it | Logged-in owner; unlocked or locked | Menu app explains before enablement | Stop disallowed interfaces; surface `localNetworkDenied`; pairing remains route-independent | Clean-user Wi-Fi, Ethernet, VPN, Tailscale, denial/recovery, and public-transition matrix; no final conclusion from ad-hoc signing |
| Bonjour discovery | Agent and iOS app | Declared `NSBonjourServices`; containing-app and iOS `NSLocalNetworkUsageDescription`; responsible-code attribution for the LaunchAgent | Logged-in owner | Client requests only when pairing starts | Explain denied/restricted state, retry after Settings recovery, and avoid treating denial as authentication failure | Clean user/VM grant, deny, Settings recovery, revocation, and network-change tests |
| Pairing-code camera | iOS app | `NSCameraUsageDescription`; foreground-only system VisionKit QR scanner | Foreground client while the explicit scanner is visible | Requested only after the user taps **Scan Pairing Code** | Stop camera immediately on scan, cancel, backgrounding, or scanner failure; explain denied/restricted recovery without weakening pairing | Physical iPhone/iPad grant, denial, Screen Time restriction, background/foreground, malformed/non-product QR, cancellation, and one-shot scan tests |
| Host identity and grants | Agent | Secure Enclave P-256 key; `AfterFirstUnlockThisDeviceOnly`, non-synchronizing/non-exportable private-key usage; service-owned security database | Logged-in owner; locked only after first unlock | Created locally during enablement; key loss requires explicit local recovery | Local suspend/revoke advances epoch; missing established key stops remote service and never silently rotates | Reboot, first unlock, lock, certificate renewal/expiry/corruption, key loss, disk-full, reinstall, migration tests |
| Client session key | iOS app | `AfterFirstUnlockThisDeviceOnly`; no synchronization | Foreground client after first unlock | Created during pairing | Device reinstall or local host revoke invalidates binding | Reboot, restore, reinstall, passcode-change tests |
| Client approval key | iOS app | Secure Enclave where available; `WhenUnlockedThisDeviceOnly` plus `userPresence` | Device unlocked for each approval | Created during pairing; explained at first approval | Key loss requires local re-enrollment; session key cannot substitute | Face ID, Touch ID, passcode fallback, enrollment, removal tests |
| Screen capture | Menu app | Screen Recording consent and usage description | Unlocked; genuine lock UI only if proved | Presented in Mac-side Control setup and required before the device grant review; runtime preflights again | Stop stream, invalidate surface revisions, publish unavailable; first grant may require relaunch | Grant/deny/relaunch/revoke, display change, lock/switch tests |
| Persistent capture | Menu app | Approved Persistent Content Capture entitlement and profile | Only states proved by public APIs | Explained with Screen Recording; entitlement is not consent | External Control disabled without approved profile or reviewed alternative | Final-identity clean-machine and review evidence |
| Accessibility focus observation | Menu app | Accessibility authorization plus an active locally approved Control descriptor carrying Keyboard and Text | Unlocked active owner | Explained in Control setup; sampled only while an authenticated primary Control sink with Text authority is active | Stop observation; destroy focus/text tokens; keep manual pixels | AppKit, SwiftUI, browser, Electron, custom, secure-field tests |
| Pointer and keyboard posting | Menu app | Post-event authority required by supported macOS; no bypass | Unlocked; lock UI only if separately proved | Requested only for Control | Release every pressed key/button and stop input immediately | Individual revocation during click, drag, modifiers, typing |
| Input Monitoring | None by default | Not requested unless a later measured feature proves necessity | N/A | N/A | N/A | Clean install confirms no unnecessary request |
| System appearance | None in MVP | No system-wide AppKit authority exists; System Events would require Apple Events usage disclosure and target-specific Automation consent | N/A | N/A | No grant is requested and no appearance action is advertised | Repository policy rejects undocumented global mutation and Agent/native-provider Apple Events; any later menu-owned light/dark Automation capability requires a new matrix and signed clean-machine evidence |
| Agent login | Containing app | Signed `SMAppService.agent` registration | After owner login | Explicit local enablement | Local disable and uninstall unregister it | Login, disable, crash, update, logout, uninstall matrix |
| Visible menu app login | Containing app | `SMAppService.mainApp` or proven equivalent | After owner login | Same explicit enablement | Quit and Disable unregisters; crash recovery cannot override intent | Login, window close, crash, explicit disable, update matrix |
| Local IPC | Agent and menu app | Audit-token/code identity and role authorization | Logged-in owner | Invisible implementation detail with health UI | Invalid peer rejected; menu-app loss revokes leases | Wrong signer, wrong role, stale version, replayed lease tests |

The network-facing Agent never receives Screen Recording, Accessibility observation, or post-event authority. The menu app never receives the remote listener, host private key, durable grants database, or provider-admission authority.
