# Interactive Control macOS input mapping v0.1

Status: normative for the deterministic, no-post mapping boundary. Real Core Graphics event construction/posting, Accessibility consent, keyboard-layout evidence, and physical release verification remain signed-platform work.

The visible menu app maps the already lease-fenced closed input union into platform event descriptions before any Core Graphics adapter runs. Pointer coordinates remain normalized unsigned 16-bit values until a current selected-display transform is applied. Scroll retains its pixel/line unit and signed bounded deltas. Text remains a transient bounded Unicode payload and is never implemented with the clipboard or retained in logs.

USB HID Keyboard/Keypad usages are not macOS virtual key codes. The first profile has an explicit mapping for usages `0x04...0x31`, `0x33...0x45`, `0x4a...0x63`, `0x67...0x6f`, and modifiers `0xe0...0xe7`. These cover ANSI letters, digits, common punctuation/control keys, F1–F20 where macOS has a stable code, navigation/arrows, common keypad keys, and left/right modifiers. Every other usage fails closed as unsupported; it is never cast or truncated into a macOS key code. This limitation is disclosed because it does not promise complete international-layout reproduction.

The mapper defensively owns the set of remotely pressed buttons and HID usages plus the current modifier mask even though the Agent has already validated stream balance. Complete modifier masks expand into ordered left/right modifier key transitions; a physical modifier transition must agree with its claimed resulting mask. Repeated down, unmatched up, or a contradictory modifier mask fails before a platform description is emitted. `reset`, lease loss, and teardown expand into deterministic releases: ascending HID usage with progressively reduced modifier flags, then primary and secondary buttons. Internal state is cleared only as those release descriptions are produced. The later posting adapter must attempt all releases and its runtime cleanup remains the authoritative completion boundary.

The unsigned Core Graphics constructor accepts only a geometry snapshot whose selected-display ID and positive safe-integer coordinate revision exactly match the execution fence. The snapshot bounds origin, size, backing scale, and rotation; resolution, scale, rotation, or display replacement therefore requires a new revision before construction resumes. It maps normalized pointer coordinates strictly inside those bounds, uses the planned pointer position for subsequent button transitions, and rejects a button whose cursor remains outside the selected display. The signed posting boundary reconstructs Core Graphics click state from two stationary, balanced clicks whose client monotonic timestamps are at most 500 milliseconds apart: the first down/up pair carries click state 1 and the second carries click state 2. Pointer motion, dragging, scrolling, reset, time regression, or a longer interval starts a new single-click sequence. This is host-local state and does not widen the closed v0 wire payload. The constructor preserves that validated click state, pixel/line scrolling, aggregate Core Graphics flags on mapped virtual-key events, `flagsChanged` for modifier virtual keys, and paired Unicode key-down/key-up events created directly from UTF-16 without clipboard use. It constructs the entire batch before sending objects to an injected construction sink whose contract forbids `CGEventPost`; stale geometry or invalid coordinates create no partial event batch.

Unsigned tests validate descriptions, held-state transitions, and constructed-event fields only. They never construct a permission prompt or call `CGEventPost`.
